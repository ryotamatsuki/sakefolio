## 1. 直接原因：確定・推定・未確認

- **確定（修正前コード）**: Google接続開始時に `setEntry(emptyEntry())` / `setPhoto(null)` が実行され、接続前に入力した記録と写真を消していた。接続ボタン自体は保存処理を実行しない。
- **確定（修正前コードとモックで再現）**: 保存完了後の一覧読込に失敗して保存を再試行すると、新規reviewIdを発行して同じ内容を二重登録できた。旧コードに新しい回帰テストを当て、Reviewsがヘッダー込み3行になり、期待2行に対して失敗した。
- **確定（コード確認）**: 写真取得失敗をすべて無言のプレースホルダーにしていた。認証、権限、404、通信、形式の区別がなかった。
- **確定（コード確認）**: PNGプレビューを表示しても、Driveには元のHEIC等を保存していた。プレビュー失敗後にも元ファイルの保存を試せた。
- **推定**: ログイン前の入力消去、または保存未実行が、当初のヘッダーのみの状態を説明し得る。
- **未確認**: ユーザーの当初の実際の保存操作・エラー・画像形式。今回の症状の単一原因は断定しない。実アカウントの修正前公開版でも、正しく入力して保存すると写真なしの新規記録は正常に保存・表示された。

## 9. 残る問題とセキュリティ

維持した条件：drive.fileのみ、アクセストークンはメモリのみ、Drive権限を公開変更しない、アカウント別保存先、403で停止、形式・容量検証、RAW数式無効化、Reactによる文字列描画・CSP。

- 複数サービス間の原子的トランザクションはない。同じ画面に残っていれば固定IDで安全に照合・再開する。自動削除・上書きはしない。
- 未完了の保存中にページを閉じる・更新する・接続解除すると、メモリ上の再開情報を失う。診断で残骸は検出できるが、ページをまたいだ自動復旧は未実装。未完了時は画面を保ち、同じアカウントに再接続して再試行する。
- 複数タブ・別端末をまたぐ排他ロックはない。別タブの新規操作は別の記録になる。
- iPhone Safari/実HEIC、別Googleアカウントとの相互隔離、実期限切れ・実ネットワーク遮断、実UIでの不正ファイル・連打は未検証。
- 一般公開前の包括的な侵入試験は未実施。CSPや依存関係検査でもXSS・サプライチェーンリスクを完全には排除できない。
