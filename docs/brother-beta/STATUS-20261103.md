## セキュリティ判定の限界

CodeQLはHigh/Criticalを拒否し、未分類の結果も安全側に失敗させます。
過去の「security-zero」という名称のプレビュー用ゲートは、プレビューブランチ向けに保持しています。
専用Betaの判定ではSARIFの重大度を確認し、High/Criticalが0件であることを求めます。
解析対象からの除外や指摘の抑制は追加していません。

CodeQLの確認済みMedium指摘は、蔵元監査CLIのファイル由来URL取得1件、専用配信検査CLIのmanifest由来URL取得2件、Wikidata報告書のJSON書込み1件です。
配信検査は正式な単一の `*.pages.dev` 生成元とファイル名、HTTPSを検証し、リダイレクトを拒否します。
これらのCLIはGoogleログインのブラウザ実行コードへimportされませんが、信頼済みの入力だけを使い、指摘が消えたとは報告しません。

Google DriveとSheetsを跨ぐ原子的トランザクションはありません。
ブラウザ終了などで孤立した写真が残る場合があり、診断で照合しても自動削除しません。
Web Locksの排他は同一オリジンのブラウザ内に限られ、別端末からの同時編集を完全に防ぐものではありません。
未確定の編集をページ終了後に自動再現する機能はなく、再読取りと競合確認が必要です。
